## 1.0.6 （2026-09-16）

### 変更概要

「実績確認・帳票出力」（`#monthly`）を顧客設計に合わせて再整備。帳票はディレクトリ上の完成ファイル直送をやめ、`v_output_*` VIEW＋`cfg_excel_output_mapping` で Excel を生成。処理を `app/monthly/services.py`／`routes.py` に集約し、帳票ボタンは一覧にデータがある様式のみ表示。フィルタ行の帳票出力を右寄せ、CSVは従来どおり最右に配置

***

### 変更詳細

| 変更番号 | 変更対象 | 変更内容 | 変更理由 |
| ---- | ---- | ---- | ---- |
| 1 | `app/monthly/services.py`／`routes.py`（新規） | 顧客設計どおりの工程パスを追加。`get_monthly_report_detail`／`get_themes_by_fiscal_year`／`get_monthly_report_total`、および `export_excel` を実装 | 設計書の `app/monthly/services.py`／`routes.py: export-excel` と実装パスを一致させるため |
| 2 | `app/common/monthly_api.py` | 実装本体を `app.monthly.services` へ移管し、本ファイルは後方互換の再エクスポートに変更 | 既存 import を壊さず設計パスへ移行するため |
| 3 | `app/common/excel_export.py`（新規） | `render_aggregate_excel` を実装。H／I-* は KPI 集計 VIEW 1行、F／G-* は `trn_report` 連携。`is_day_batch`＋`slot_number` 対応 | 顧客仕様の VIEW＋マッピング帳票出力に合わせるため（仮ファイル直送を廃止） |
| 4 | `app/service/monthly*api/*_service.py` | Init／FiscalYear／CSV／Export を `app.monthly.services`／`routes.export_excel` 経由に変更 | サービス層から設計パスを直接呼ぶため |
| 5 | `app/dto/monthlyinitapi`／`monthlyfiscalyearapi`／`monthlyexportapi` | `periodtype`／`reportid` 等を追加 | 月次／年次の帳票ボタン絞込と報単指定に必要のため |
| 6 | `app/controller/commonfunctioncontroller.py` | 帳票成功時の一時 xlsx を `after_this_request` で削除。コメントを VIEW 生成経路に更新 | 生成ファイルの残留防止と実装経路の明確化のため |
| 7 | `static/mockup/js/monthly.js`／CSS | 帳票出力を右寄せ（CSV直前）。`periodtype` を API へ送信。年次ボタンに I-6 を含め、要実施年月は API の `requires_yearmonth` に従う | 報告書画面と同様の右配置、および月次／年次の正しい帳票群表示のため |
| 8 | `app/monthly/services.py`（`filter_export_forms_by_data`） | 一覧 KPI が無い期間は帳票ボタン非表示。F／G は当該期間の登録済み報告書がある様式のみ表示 | 「一覧にデータがある様式だけ帳票ボタンを出す」要件のため |
| 9 | `data/monthly_report_exports/README.md` | 配置物はテンプレートのみである旨を明記 | 完成帳票の直置き誤解を防ぐため |
| 10 | `templates/app.html` | `monthly.js?v=20` にキャッシュbust更新 | ブラウザが旧 JS／CSS を使い続けるのを防ぐため |
